# 2026-09-06 代码复核与操作审计

## 范围与基线

复核基线为公开仓库 `main` 的 `d6ddacd`。对象是 `iptables_Forward.sh`、中文向导、README 和新增回归测试。工作目录中的真实客户端配置、密码、密钥、服务器概览与原始检查日志不属于公开提交内容。

本次保持 A -> B 以及 C -> A -> B 的角色与原有交互菜单。没有在生产机器上执行新版安装/删除向导，也没有重新编排生产通信端口。网络测试在独立命名空间完成。

## 缺陷与修复

| 等级 | 原问题与触发条件 | 修复与效果 |
| --- | --- | --- |
| P1 | `save_rules` 保存整张表，恢复服务执行全量 restore；系统重启或恢复时可能覆盖 Docker/UFW/后续添加的规则 | 只保存 A2B 链，使用 `--noflush` 恢复；旧全量持久化文件仅迁出 A2B 部分，迁移前备份；错误不再吞掉 |
| P1 | 同一 TCP/UDP 入口端口改目标时只追加规则，旧 DNAT 优先命中 | 从原自有链生成候选集，替换相同协议/端口的旧规则；先内核校验再加载，失败尝试恢复原自有链 |
| P1 | WireGuard 接口名直接拼接配置路径；IP 只按是否包含冒号/点粗略判断；CIDR/Endpoint 可含非法值 | 使用 Python 标准库 `ipaddress` 校验 IP/CIDR，限制接口名与 Endpoint；新建模式拒绝覆盖已有配置/接口 |
| P1 | 开启 IPv6 forwarding 但不处理 RA，依赖 SLAAC/RA 的出口可能失效 | 在开启 forwarding 前，为原本接收 RA 的接口设置 `accept_ra=2`；不强制开启原本禁用 RA 的接口 |
| P1 | Nginx 在校验前覆盖正式配置，重载失败再强制重启 | 先校验独立候选目录；应用失败恢复对应旧文件；不强制重启原运行服务 |
| P2 | 空监听地址的 DNAT 能匹配经过本机转发但并非发给本机的包，SNAT/放行规则边界过宽 | DNAT 限定目的类型 LOCAL；后续规则匹配 DNAT 连接与原始入口端口 |
| P2 | 添加入口时没有检查已有监听服务，可能劫持 SSH/网站端口 | 写入前检查同协议族 TCP/UDP 监听；仅允许更新本项目自己的 Nginx 监听 |
| P2 | 查看菜单会安装依赖/持久化工具；删除入口无总确认；保留 WG 时却删除 UDP 放行 | 查看只读；新增退出选项和删除总确认；保留 WG 时重新保存必要 UDP 放行 |
| P2 | 向导 EOF 可能在循环或命令替换中被解释为默认输入 | 必填、默认值、端口和是/否提示遇 EOF 明确退出 |
| P2 | 端口按 Bash 默认数制处理，`00080` 被视为无效八进制；超长数字可能溢出 | 限长、十进制校验并规范化端口 |
| P2 | NAT64 按字符串拼接，对非 `/96` 只警告后继续 | 使用标准库按位合成，仅支持无主机位的 IPv6 `/96` 网络 |
| P2 | 统一设置缓冲区/FIN 超时，并把 WireGuard 描述为必然更快 | 调参改为可选，只提高偏低的容量/队列；保留原回收、缓冲区、rp_filter；默认复用现有路由 |
| P2 | 无版本化回归和面向新手的完整验收流程 | 新增核心/真实网络测试、持续集成、中文端口对照表、安装与检查步骤、失败定位和回退边界 |

## 验证方法

静态检查使用 Bash 语法检查、ShellCheck 0.11.0 和 `git diff --check`。官方 Windows ShellCheck 压缩包的 SHA-256 与 GitHub 发布摘要一致。

Linux 实测环境为 Debian 13、iptables 1.8.11（nf_tables 后端），使用本机/入口/落地三个隔离网络命名空间、veth、默认 DROP 转发策略和真实 TCP/UDP 回显服务。Nginx 二进制和 stream 模块从发行版包解包到专用测试目录，没有安装系统级 Nginx 服务。systemd 启停命令由测试适配器转换为启动/重载这个真实独立 Nginx 进程。

已完成的验收包括：

- 端口/IP/CIDR/接口名/Endpoint/NAT64/EOF/菜单取消回归。
- IPv4 -> IPv4、IPv6 -> IPv6 的 TCP 与 UDP 往返数据校验。
- IPv4 -> IPv6、IPv6 -> IPv4 的真实 Nginx TCP 与 UDP 往返数据校验。
- 相同入口端口更新后新连接到达新目标，旧规则被移除。
- 来源 CIDR 拒绝与允许；默认 FORWARD DROP 下合法映射仍可工作。
- 重复恢复不增加重复跳转、不删除其他链、不改默认 DROP 策略。
- 无效 NAT 候选不改变原规则；Nginx 重载失败时旧文件和原服务保留。
- IPv6 forwarding 后原启用 RA 的接口保留 RA 接收能力。
- 对已有本机监听端口的冲突拒绝。

过程中一次错误的 conntrack 参数在内核候选校验阶段被拒绝，随后修正为受支持的 DNAT 状态和回复方向匹配，再通过整套测试。首次在小内存 VPS 上运行 ShellCheck 被系统终止，退出码 137；之后将静态检查移到工作站。后续一轮复测超时且留有临时 Nginx，按已核实的测试配置路径定位并清理；测试改用单 worker、快速停止和信号清理，受限时长的完整复测通过。最终增加最低可用内存检查，建议只在 CI/测试机运行：网络命名空间不隔离宿主机内存。错误记录保留在私有审计目录，没有把失败结果写成通过。

## 新思路与取舍

采用“先验证候选、再应用”的规则/配置流程，比继续堆叠全局 sysctl 更直接地改善维护可靠性。公共服务端口检查、退出/取消提示和实际出口验收也属于可用性改进。

保留内核 NAT 作为同协议族的默认路径。纯 NAT 中转不终止 TCP，调整 A 的 TCP 拥塞控制不会替客户端控制转发流量。WireGuard 用于加密或私网需求；不把额外封装宣传成无条件低延迟。没有为了性能更换生产代理协议、B 的端口或 Reality 参数。

Nginx 的 TCP 上游开启 keepalive；UDP 会话空闲时间从 1 小时改为 5 分钟，减少长期空闲会话占用。真实 TCP/UDP 回显通过，但不同应用的长时静默行为仍需单独验收。

## 未覆盖事项

没有重启生产 VPS，没有进行真实 UFW/Docker 重载、systemd 开机顺序、WireGuard 两端密钥交换和公网 NAT64 网关全链路测试；这些不能由命名空间测试代替。新建 WireGuard 尚不是跨两台机器的原子部署，B 端仍需操作者安装导出的配置。修改系统 sysctl 的整个向导也不是全局事务。

规则恢复按表进行，存在多个表之间的短暂切换窗口；没有清理全机 conntrack，已建立连接要自行重连。第三方防火墙管理器重载后，应复查 A2B 跳转。Nginx 重载成功的信号返回不代表全部应用已完成握手，仍需客户端验收。

本次没有带宽基准测试，不报告吞吐或延迟提升百分比。客户端 DNS 防泄露、浏览器行为和 Windows TUN 不属于这份 Linux 端口转发工具的验收范围。

## 测试资源事件

后续内核日志确认，小内存测试宿主机发生过全局 OOM，受影响的进程不仅有 ShellCheck 和测试 Nginx，还包括用户会话进程以及一个原有 coturn 服务进程。coturn 自动重启一次，收尾检查为 active/running，原代理链路重新实测可用。另一个原有容器也观察到重启，收尾为 healthy；不能仅凭时间接近认定具体原因。

这次测试没有充分隔离资源压力。最终测试已经限制 Nginx worker、增加停止信号清理和最低可用内存门槛；后续验证应优先使用 CI/专用测试机。临时 Nginx、回显服务和测试网络命名空间已清理。所有失败、资源事件、恢复状态以及成功结果均保留在私有操作证据中。

公开提交 `d68b94f` 的 [GitHub Actions 回归](https://github.com/Borisgohard/a2b-forward/actions/runs/33997858613) 已在 Ubuntu 24.04 上通过，包含静态检查、核心回归和真实隔离网络测试。

## 操作与发布

1. 克隆用户指定的原仓库，保留历史和 main 分支，不初始化无关仓库、不强制推送。
2. 只读核验生产链路；获取官方文档及工具发布摘要。
3. 对确认的问题实施上述修改，加入回归与失败注入测试。
4. 在工作站做静态检查，在隔离 Linux 网络做真实转发和回滚检查。
5. 重写中文 README，说明端口角色、每一步的输入、预期现象、管理和回退。
6. 发布前检查提交文件与实际密钥值无交集，保留私有部署文件在仓库外。
7. 正常推送原仓库 main，持续集成状态以 [GitHub Actions](https://github.com/Borisgohard/a2b-forward/actions) 为准。

审计记录包含实施依据、结果和覆盖边界；原始命令输出与包含真实 IP 的部署材料留在本地私有审计目录。
